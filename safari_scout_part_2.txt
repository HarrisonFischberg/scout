5. Conversation flow
	•	The user submits a message in the panel.
	•	The panel gathers context (section 6) according to the user's settings.
	•	The panel opens a streaming request to the Scout server.
	•	Streamed events updte a conversation store keyed by message ID, with statuses pending → streaming → complete or error.
	•	The UI renders text, citations, code blocks, talbes and math as they arrive.
	•	If the stream contains a tool request, the panel runs it through the tool host (section 7), posts the result back with the same request_id, and the server coninues the same answer.
	•	If the stream drops, the panel resumes from the last received position, with no duplicated text.
	•	The user can stop an answer while it's being generated.
