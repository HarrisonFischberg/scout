# QA pass, 2026-10-29

Senior-QA pass over chat routing, Scout mode (browser control), Find coupons
and the trust boundaries, run on the owner's Mac (macOS 27.2, Node 24.22)
inside the Claude Code sandbox. Each fix below has a test that failed first.

## Architecture map (paths traced)

- **Chat:** panel `src/popup.ts` `connect()` picks the session (no key + Apple available: Apple only; key + Apple first on: `appleFirst`), sends `chat.start` with `model: apple-on-device` and a `fallback` → worker `src/server/worker.ts` → `ScoutServer.execute` (`src/server/engine.ts`): `askApple` (one reply, no tools) → `appleCouldNotAnswer` / `appleRepeats` / any Apple error → `handoff` event → key's model with tools and web search, up to 6 rounds → `done`, saved to history. Apple runs natively: `src/providers/apple.ts` → `browser.runtime.sendNativeMessage` → `apple/Extension/AppleModelBridge.swift` (`SystemLanguageModel.default`, `LanguageModelSession.respond`). Not callable from extension JavaScript directly.
- **Scout mode:** model action → `src/actions/vocabulary.ts` parse → permission gate and sensitive-action confirmation (`src/agent/task.ts`, `src/safety/classifier.ts`) → `performTaskAction` (`src/actions/task.ts`, probes before acting) → content-script adapter `src/actions/task-dom.ts` → next observation.
- **Find coupons:** `src/coupons/job.ts` → `openCouponTester` (cart API first, else the page's coupon box) → candidates from quiet reads and web search (`src/coupons/codes.ts`, `candidates.ts`) → `runCouponSearch` (`src/coupons/finder.ts`): baseline, each code measured against it, combos where the store stacks, winner re-applied and confirmed, else original codes restored.
- **Trust boundaries:** `classifySender` and the per-type sender and schema registry (`src/bridge/messages.ts`); untrusted page text fenced in `untrusted_page_content` (`src/chat/prompt.ts`); tool results fenced in `tool_result` (`src/server/engine.ts`); Markdown rendered with `createElement`/`textContent` and http(s)-only links (`src/chat/markdown.ts`); keys only in the Keychain via native messaging, read by the worker and panel, never by content scripts.

## Findings and fixes (one PR per area)

| # | Severity | Area | Finding | Fix | Test |
| --- | --- | --- | --- | --- | --- |
| 1 | High | Routing | A native call to Apple's model that never answers hung the chat with no fallback, and Stop could not end it (the native await was not abortable). | `createApple` races each call against Stop and a 60 s limit; then the key's model takes over, or a plain error without a key. | `tests/unit/apple-first.test.ts` "a stuck Apple model" |
| 2 | High | Coupons | If the shopper changed the cart mid-run, a weaker code measured on the smaller cart was reported as saving the difference and applied over a better code. | Cart-API tester puts the original codes back before applying the winner and checks the total still matches the baseline; if not, says the cart changed and leaves the shopper's codes. | `tests/unit/coupon-properties.test.ts` |
| 3 | Medium | Browser control | Controls inside `<fieldset disabled>` were probed as enabled (click "succeeded" and did nothing); `fill_field`/`type` wrote into read-only fields. | `:disabled` check (fieldsets included) in both executors; type and fill refuse read-only fields. | `tests/e2e/task-dom.spec.ts` |
| 4 | Medium | Security | A page title went inside the untrusted fence uncleaned, so a title with the closing tag ended the fence; variant spellings of the tag also got through. | Shared `unfence()` for text, title and address in chat, `read_page` and Scout summaries; `tool_result` tag tolerance. | `tests/unit/chat.test.ts` |
| 5 | Low | Security | Provider citations were not scheme-checked before becoming panel links (saved history was). | Engine drops non-http(s) citations. | `tests/unit/server.test.ts` |
| 6 | Low | Tests | Two unit tests depended on the machine (UTC clock; lock order on Node 24, which ships `navigator.locks`). | Tests fixed, no product change. Added a CI workflow (typecheck, lint, unit, release-bundle check; no keys). | `.github/workflows/checks.yml` |

Open, not fixed (product decisions or larger work):

- **Apple refusals hand off to Claude.** A guardrail refusal from Apple (`refused`) and short "I can't" replies go to the key's model (owner choice 2026-10-27). The brief asks not to provider-hop around a refusal; Claude applies its own safety policy, so this is not a bypass, but it is a decision for the owner.
- **`contenteditable` in the coupon executor** (`src/actions/executor.ts`) is not typeable (Scout mode's adapter handles it).
- **Postconditions:** Scout mode reports "Filled" from the write, not from reading the value back; the loop re-observes after each action, which catches most rejections.
- **Snapshot `disabled`** (`src/snapshot/snapshot.ts`) reads only the attribute, so the model can still see a fieldset-disabled control as enabled; the action now fails with "disabled" instead of succeeding.
- **Page-path coupon tester** has no "cart changed" check (only the cart-API path).
