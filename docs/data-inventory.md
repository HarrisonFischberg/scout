Button on webpages (T032, `src/edge.ts`): on from a fresh install
(2026-10-17); it appears only on sites the user already let Scout access.
Turning it back on in Settings asks Safari for access to every site (the
user may grant fewer). The edge script is
registered only for granted origins and reads nothing from the page; it only
draws the tab. A tap sends one `panel.open` message (no data) to the worker,
which opens the toolbar panel; no new flow or recipient.

Part 3 (2026-10-17): Scout mode runs in the background worker
(`src/server/task-host.ts`, `src/agent/task.ts`). The worker injects
`content.js` and `overlay.js` into the task's tab on demand; the overlay reads
nothing from the page and only draws the border, the click marker, and the
control pill, whose buttons send a pause / resume / stop message for that tab's
task. Screenshots follow the per-site screenshot setting. No new recipient: the
page structure, action results, and screenshots go to the user's chosen
provider, after the per-task question. The sensitive-action confirmation runs
on the device from the action type and its target; a server flag cannot skip
it. The consent wording (version 2) now names Scout mode instead of Control
Browser and says that Scout mode sends the page again after each step; the
version was not bumped (the per-task question and the screenshot setting are
the gates for the new flow), which counsel's pending review of version 2
(launch blocker 23) should confirm.

Part 2 (2026-10-16): chat answers now run in the background worker (the
"Scout server", `src/server/engine.ts`), which reads the key from the Keychain
over native messaging, checks consent, and calls the provider directly. There
is still no hosted Scout for Safari server and no new recipient. The panel
gathers context and runs tool requests through the worker's tool host and
permission gate (`src/tools/host.ts`, `src/permissions/gate.ts`).

Provider calls (T005, `src/providers/`): requests go directly from the
extension to `api.anthropic.com/v1/messages` or `api.openai.com/v1/responses`
with the user's key in a header only (never in the body). Every popup request
to a provider API goes through `gatedFetch` (`src/settings/consent.ts`), which
refuses it unless the user allowed sharing with that provider (2026-10-16). Error messages shown
to the user never include provider response bodies. No new recipient beyond the
vendors above.

Not collected: analytics, crash telemetry, advertising IDs, cookies set by
Scout for Safari. Any addition needs a new row and owner approval first.

Vendors (user-selected, BYOK): Anthropic (Messages API), OpenAI (Responses
API). Apple (App Store distribution) once released.

Key test (T006, `apple/App/ProviderSetup.swift`): the host app sends one
read-only GET to `api.anthropic.com/v1/models` or `api.openai.com/v1/models`
with the user's key in a header, when the user presses "Test key", and only
after the user chose Allow on the consent sheet for that provider. Nothing is
logged or stored from the response; only the status code is used. The key is
then written to Keychain on "Save key". No new recipient beyond the vendors
above. The app sandbox gained `com.apple.security.network.client` for this.
